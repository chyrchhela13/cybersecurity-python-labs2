## Завдання 1

```bash
python -m labs.lab02.main demo
```

Реалізовано User, Admin, Session, AuditRecord, AuditLog, UserAccount.

Admin успадковує User.
UserAccount об'єднує User, Session та AuditLog через композицію.
AuditRecord використовує @dataclass.

Паролі зберігаються як PBKDF2-HMAC-SHA256 із випадковою
16-байтовою сіллю та 600000 ітераціями.
Порівняння виконується через hmac.compare_digest.

Пошта перевіряється через @property та регулярний вираз.
Час сеансу й аудиту — UTC. Таймаут — 900 секунд.
Невдалий вхід не подовжує сеанс.
Дозволені ключі UserAccount: user, session, audit_log.
Невідомий ключ — KeyError, неправильний тип — TypeError.

## Завдання 2

Вхідний файл: data/data_v06/passwords.txt із навчального архіву.

```bash
python -m labs.lab02.main analyze --wordlist labs/lab02/data/data_v06/passwords.txt --min-length 8 --top-masks 5 --output-stats labs/lab02/password_stats.json
```

Параметри:
- --wordlist: обов'язковий шлях до словника.
- --min-length: додатний поріг довжини, типово 8.
- --top-masks: додатна кількість масок, типово 5.
- --output-stats: обов'язковий шлях до JSON-звіту.

Файл читається генератором у UTF-8 із підтримкою BOM.
Порожні рядки пропускаються. Пробіли зберігаються.
Дублікати враховуються окремо.
Слабкі паролі — ті, що коротші за --min-length.

Маски визначаються регулярними виразами:
- U: великі латинські літери;
- l: малі латинські літери;
- d: цифри 0–9;
- w: пробільні символи;
- u: інші Unicode-літери за шаблоном [^\W\d_];
- s: решта символів.

Сусідні однакові категорії об'єднуються.
Приклад: Password1! → Ulds.
Ці правила явно визначені через неоднозначні приклади в методичці.

Counter підраховує маски.
Сортування: кількість за спаданням, потім маска за зростанням.
JSON містить загальну статистику, всі маски та топ масок.
Паролі до звіту не записуються.
logging показує прогрес кожні 10000 записів і підсумок.

Очікуваний результат:
- паролів: 44;
- коротших за 8: 10;
- частка коротких: 22.73%;
- середня довжина: 9.98;
- топ масок: l — 10, Ulds — 7, d — 3, Uds — 2, ld — 2.
